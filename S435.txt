## Test Scenario & Description 🔍
The test suite validates the following:
- Visual clarity & spacing: card padding, title font-size, and whitespace.
- Hierarchy: card title sizes and meta text differences.
- Buttons: primary button color, hover box shadow, pointer cursor and unified style.
- Iconography: same icon sizes and vertical alignment.
- Accessibility: color contrast, visible focus outlines, presence of ARIA labels (role attributes), keyboard focus behavior.

Test inputs/outputs are plain JSON vectors in test_data.json and per-project `data/test_data.json`. Each test object includes:
- `test_id`, `description`, `url`, `steps`, `selector`, `expected`, `screenshot`.

Example test entry from test_data.json:
{
  "test_id":"card_spacing",
  "description":"Assert card padding >= 16px and title font-size >=16px",
  "url":"http://127.0.0.1:8001",
  "selector":".task-card",
  "expected": {"padding-left": 16, "padding-right": 16, "padding-top": 16, "padding-bottom": 16, "title_font_size": 16},
  "screenshot":"screenshot_pre_card_spacing.png"
}

Acceptance thresholds include:
- Card padding >= 16px
- Title font-size >= 16px
- Primary button color consistent (#0d47a1 baseline, #0b63d6 improved)
- Icon sizes unified (baseline 18px vs improved 24px)
- Contrast ratio threshold >= 4.5:1 for body text
- Focus outline visible in improved UI >= 3px bright outline
- Pass/fail based on computed CSS values or thresholds for a11y

## Test Implementation & Automation 🔧
- Technologies: Python (3.x), Playwright, Flask, Pillow (for image diffs).
- Each project's `tests/run_tests.py`:
  - Starts a Playwright Chromium instance in headless mode
  - Opens the assigned server URL (127.0.0.1:8001 for baseline, 127.0.0.1:8002 for improved)
  - Executes test steps from the JSON data (open, hover, query)
  - Captures element or full-page screenshots
  - Measures computed CSS values via `window.getComputedStyle` (padding, font-size, background-color, box-shadow)
  - Simulates hover & focus to read hover styles and focus outline CSS
  - Computes contrast ratio using the WCAG luminance formula (no external a11y libs required)
  - Captures console messages (JS errors, warnings) to `log_pre.txt` or `log_post.txt`
  - Output:
    - `results/results_pre.json` / `results/results_post.json` (structured test outputs)
    - `logs/log_pre.txt` / `logs/log_post.txt` — console messages & logs
    - `screenshots/` — `screenshot_pre_ui.png`, `screenshot_pre_<testid>.png`, `screenshot_post_ui.png`, `screenshot_post_<testid>.png`

Notes:
- The tests measure a11y-related properties programmatically and compute pass/fail; they are not a substitute for full accessibility audits, but they follow the required checks (contrast, focus outlines, ARIA presence).
- Pixel diffs are computed using Pillow `ImageChops.difference`. The script computes percent of nonzero pixels and writes out diff images.

## How the Tests Validate Key Criteria 🔬
- Visual clarity: visual diffs show reduced density and added whitespace in the improved UI.
- Spacing & Hierarchy: `card_spacing` checks compute padding and font size to ensure these increase in the improved design.
- Button Consistency: `button_consistency` checks background-color consistency and hover box-shadow existence/values for `.btn-primary`.

## Limitations & Caveats ⚠️
- Pixel-perfect diffs are brittle across OS, install fonts, and rendering engine differences. Tests rely on thresholds and percentages rather than strict exact matches where applicable.
- Playwright browser rendering may vary by machine OS/version. Run tests locally for consistent comparison.
- The tests are automated and check styles and computed values; a manual accessibility audit is recommended for a full compliance assessment.
- The tests do not simulate mobile/responsive breakpoints — extending tests to multiple viewports is a recommended follow-up.
